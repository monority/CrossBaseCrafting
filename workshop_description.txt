[h1]CrossBaseCrafting[/h1]

Share regular chests and food containers between all of your existing bases. Crafting stations can use materials stored in your other bases without manually moving items.

[h2]Features[/h2]
[list]
[*] Shares regular storage chests and food containers across bases
[*] Supports crafting and building resource access
[*] Works with multiple bases belonging to the same guild
[*] Automatically discovers and updates storage modules
[*] Written in fast native code and designed to stay out of your way: it does not get in the way of your frame rate, even while the world is still loading around you
[*] Safely restores the original game state when the world changes
[/list]

[h2]Requirements[/h2]
[list]
[*] [url=https://steamcommunity.com/sharedfiles/filedetails/?id=2834209225]UE4SS[/url] for Palworld
[*] A UE4SS installation that supports C++ mods
[/list]

[h2]Installation[/h2]
[olist]
[*] Subscribe to this Workshop item.
[*] Start Palworld once so UE4SS can install the mod files.
[*] Open UE4SS Mod Management and enable [b]CrossBaseCrafting[/b].
[*] Apply the change and restart the game if requested.
[*] After restarting, confirm that [b]Mods/NativeMods/UE4SS/Mods/CrossBaseCrafting/dlls/main.dll[/b] exists on disk.
[/olist]

If the [b]CrossBaseCrafting[/b] folder does not appear even though Mod Management shows the mod as enabled, the game never copied the package: unsubscribe, delete the folder if it exists, resubscribe, and start Palworld again. A leftover [i]CrossBaseCrafting : 1[/i] line in [b]mods.txt[/b] is not proof that the files are installed.

For a manual installation, the mod folder must contain [b]dlls/main.dll[/b] and [b]Info.json[/b]. Do not install the C++ source files or build folders.

[h2]How it works[/h2]

Place regular chests and food containers in your bases. Once the storage graph is ready, the mod registers the available containers across bases and exposes the appropriate shared resources when crafting or building.

[h2]Compatibility and safety[/h2]
[list]
[*] Designed for single-player and host (listen-server) worlds; dedicated servers are not supported by this build
[*] The mod only targets storage modules discovered in the current world
[*] Original container registrations are tracked and restored during world transitions
[*] Shared containers are removed from your inventory as soon as you leave a base, so base contents never follow you
[*] If something unexpected goes wrong, cross-base sharing switches itself off instead of letting the game crash
[*] Palworld updates may require a compatibility update
[/list]

[h2]Troubleshooting[/h2]

If the mod does not load, verify that UE4SS is running, [b]CrossBaseCrafting[/b] is enabled, and the UE4SS log contains [i]Starting C++ mod 'CrossBaseCrafting'[/i].

If cross-base access does nothing while the mod is loaded, the UE4SS log now states the exact reason the resource union was disabled (for example a network client or a dedicated server).

If a Palworld update ever breaks the mod, you can disable the parts that touch the game without waiting for a new release. Create an empty text file next to [i]Palworld-Win64-Shipping.exe[/i] and restart the game:
[list]
[*] [b]crossbase_no_detour.txt[/b] - disables the native build-material counter
[*] [b]crossbase_no_live_union.txt[/b] - disables player-inventory injection (crafting/build stop working across bases)
[*] [b]crossbase_no_persistent.txt[/b] - disables the whole cross-base storage union
[/list]
Delete the file to restore normal behaviour. Nothing else is required.
